## 3. Authoritative prior decisions

- Any authenticated Actor may create a Workspace (no PlatformPermission).
- Actor ≠ Membership (OPEN A).
- Bootstrap ≠ data-plane (no Membership, no `AuthorizationContext`).
- Caller `actorId` / `workspaceId` never authority (SEC-001).
- Identity owns Workspace, Membership, Role assignment, idempotency slot.
- Gateway is the invocation façade.
- Product/Capability = NONE.

---

## 4. Gateway role

Gateway is the **in-process application invocation boundary** (`createPulseV2Gateway`).

For bootstrap it: validates required metadata, forwards opaque proof, resolves trusted Actor, invokes Identity, returns Identity result or `V2_*` deny.

It does **not** persist Workspace/Membership, assign Role, or own the idempotency slot.

## 5. Bootstrap method surface

**Selected name:** `createWorkspace`

Evidence:

| Source | Pattern |
|--------|---------|
| Identity operation | `Identity.createWorkspace` |
| Invocation design | conceptual `Gateway.createWorkspace(...)` |
| Domain ops | `createOrder`, `createTripFromOrder` (create + entity) |
| Data-plane | sibling method `execute`, not an `execute` operation string |

Conceptual (not implemented):


`execute` remains `{ domain, operation, payload, ... }`. Bootstrap is **not** `execute({ domain: "identity", operation: "createWorkspace" })`.

## 6. Request contract

**Exactly three caller fields.** No other required or authoritative fields.

| Field | Required | Type | Generated by | Gateway |
|-------|----------|------|----------------|---------|
| `identityProof` | **Yes** | `string` | Caller / future Auth as opaque proof | Trim; wrap as `IdentityProof { value }`; **do not** interpret as Actor id |
| `correlationId` | **Yes** | `string` | Caller (same as `execute()`) | Require non-empty; pass through; echo on response |
| `idempotencyKey` | **Yes** | `string` | Caller (Command Envelope convention) | Require non-empty; pass through; **not** a credential |

Missing/blank `correlationId` or `idempotencyKey` or `identityProof` → `V2_GATEWAY_INVALID`.

**Not in this request** (not authority; not trusted if a future transport smuggles them):

`actorId`, `workspaceId`, `membershipId`, `role`, `permissions`, `capabilities`, `tenantId`, `payload` Workspace metadata.

If a caller supplies `workspaceId` anyway → `V2_WORKSPACE_DENIED` (self-join). If a caller supplies `actorId` ≠ trusted Actor → `V2_ACTOR_DENIED` (SEC-001), same as `execute()`. Preferred: omit them from the typed request.

## 7. IdentityProof handling

Same as `execute()` / OPEN A / SEC-001:

```text
identityProof (string)
    ↓
IdentityProof { value }   // Gateway does not parse JWT / Auth
    ↓
IdentityPort.resolveActor(proof)
    ↓
trusted actorId
```

Gateway must **not**: treat `proof.value` as `actorId`; derive Actor locally; trust `request.actorId`; infer Actor from Membership; query `auth.users` or `organization_members`.

---

## 8. Correlation handling

```text
Caller.correlationId
    → Gateway (required)
    → Identity.createWorkspace(..., correlationId)
    → response.correlationId = this request’s id
```

Retries: **new** `correlationId` allowed; **same** `idempotencyKey` converges (`9ab20dee`). Not interchangeable.

---

## 9. Idempotency handling

Gateway **receives** and **forwards** `idempotencyKey`. Does **not** generate, hash, store, or scope by Workspace.

Identity uniqueness:

```text
(trusted actorId, Identity.createWorkspace, idempotencyKey)
```

Key ≠ authorization. Replay of Identity identifiers is Identity-owned; Gateway still echoes **current** `correlationId`.

---

## 10. Trusted Actor resolution

After required-field checks:

```text
resolveActor({ value: identityProof.trim() })
  fail → V2_UNAUTHENTICATED
  ok   → trustedActorId
```

**No** `resolveMembership`. **No** `AuthorizationContext`.

## 11. Identity invocation boundary

After trusted Actor:

```text
Identity.createWorkspace({
  actorId: trustedActorId,       // from resolveActor only
  correlationId,
  idempotencyKey,
})
```

Future façade (not implemented): `IdentityPort.createWorkspace` with that argument object. Gateway calls the port; Experiences call Gateway.

## 12. Response contract

Do **not** use `V2GatewayResult` (`domain` + `operation` + `data`) — that is data-plane.

### Success (Identity result, Gateway transport)

```text
{
  ok: true
  workspaceId: string        // Identity-issued
  membershipId: string       // Identity-issued
  actorId: string            // trusted creating Actor (echo)
  membershipStatus: "active"
  correlationId: string      // this request
}
```

Replay of a completed slot returns the **same** Identity identifiers; `correlationId` is the retry’s.

**Not returned:** `AuthorizationContext`, `role`, permissions, capabilities, Product, Tenant, Organization.

After success, data-plane uses `execute()` with `identityProof` + optional `membershipId` selector — not payload `workspaceId` as authority.

### Failure

Existing `{ ok: false, code, message, correlationId }` (`V2GatewayError`).

---

## 13. Error contract

No new catalog. Identity/Workspace/Membership failures stay Identity-semantic; Gateway maps to existing `V2_*`.

| Code | Origin | When |
|------|--------|------|
| `V2_GATEWAY_INVALID` | Gateway | Missing/blank `correlationId`, `idempotencyKey`, or `identityProof` |
| `V2_UNAUTHENTICATED` | Identity `resolveActor` | Proof invalid / Actor not found |
| `V2_ACTOR_DENIED` | Gateway | Extra `actorId` claim ≠ trusted Actor |
| `V2_WORKSPACE_DENIED` | Gateway | Extra `workspaceId` (or equivalent) as authority |
| `V2_WORKSPACE_CREATE_FAILED` | Identity | Atomic create failed; idempotency in-flight/conflict treated as **not success** (fail-closed; no second Workspace). Pending retry is **not** `ok: true`. |

Membership-create failure is **not** a separate code (atomicity). No domain codes.

## 14. Bootstrap vs data-plane distinction

```text
createWorkspace(request)
  → validate metadata
  → resolveActor
  → Identity.createWorkspace
  → Identity result
  NO resolveMembership
  NO AuthorizationContext
  NO commerce/execution dispatch

execute(request)
  → validate correlationId
  → resolveActor
  → resolveMembership
  → AuthorizationContext
  → domain dispatch
```

Do not special-case `execute()` for Workspace create. Nested `execute` from Commerce stays injected `dispatch(ctx)` (SEC-005). Bootstrap must **not** call public `execute()`.

## 23. Decision

The public V2 Gateway contract for Identity Workspace bootstrap is:

```text
createPulseV2Gateway().createWorkspace({
  identityProof: string,      // required, opaque
  correlationId: string,      // required
  idempotencyKey: string,     // required, caller-supplied
})
```

Trusted Actor: `IdentityPort.resolveActor({ value: identityProof })`.  
Then Identity: `createWorkspace({ actorId: trusted, correlationId, idempotencyKey })`.  
Success: Identity identifiers + this `correlationId`.  
Errors: existing `V2_*`.  
`execute()` unchanged.
